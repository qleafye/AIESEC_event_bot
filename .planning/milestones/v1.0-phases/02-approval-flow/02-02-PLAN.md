<objective>
Split the `finalize_registration` monolith (`handlers/registration.py:772`) into a status decision + two outcomes, and gate the bot on approval. A finalized registration now computes `status` from the active form type and the per-form moderation setting (APP-07): `manual` forms land in `pending` (a "заявка отправлена" acknowledgement, no menu — APP-01), `auto` forms land in `approved` and immediately get the welcome via a new reusable `approve_user()` (the same function the manager's manual-approve in Plan 03 will call). `ensure_registered` (`handlers/user_actions.py:27`) now admits only `approved` users (APP-03), and a `rejected` user can re-apply from `/start` (D-05a).

Capability delivered: organizers flip moderation per form in settings; delegates on a moderated form are told their application was submitted and cannot use the menu until a manager approves; auto-form delegates are unaffected; the 590 live `approved` users keep full access; a rejected delegate can register again.

Decisions covered (traceability): D-01/D-02/D-03 (settings-driven `short_approval`/`full_approval`, defaults full=manual / short=auto, status decided by form+setting). D-04 (pending → "заявка отправлена", no menu; approved → existing flow). D-05 (ensure_registered approved-only gating). D-05a (rejected re-apply on /start). D-15 (per-submission admin ping gated by `pending_notify_mode`, default batched).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram user → bot | /start and menu actions from pending/rejected users attempt to reach gated features |
| Settings → finalize | admin-controlled approval-mode strings drive the pending/approved decision |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-0202-01 | EoP | ensure_registered | mitigate | Menu actions are admitted only for status=='approved'; pending/rejected are denied with a message and False. Tested via _gate_decision. |
| T-0202-02 | Availability | 590 live users | mitigate | Legacy/missing status falls open to True (approved), and `users.status DEFAULT 'approved'` means existing rows already read approved — no live user is locked out by the migration. |
| T-0202-03 | Spoofing/escape | approve_user / submission ack | mitigate | approve_user sends to the user's own telegram_id (no cross-user send); complete_text already uses HTML from trusted settings; submission ack is a static string. |
| T-0202-04 | DoS (notify storm) | admin notify | mitigate | Pending submissions only ping admins when pending_notify_mode=='instant' (default batched), so a registration surge does not flood managers (D-15). |
</threat_model>
