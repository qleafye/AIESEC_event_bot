# Phase 4 + YL'26 — Ручное тестирование

Чек-лист ручной проверки на тестовом боте/БД. Бот **универсальный**: один код, два
профиля настроек — **YouLead (форум)** и **Summit (конференция / RusCo)**. Сначала общий
блок и регрессия, потом два событийных сценария.

Легенда: `[ ]` не проверено · `[x]` ок · `[!]` баг. «0 хардкода» — всё правится в `/admin`.

---

## A. Общая регрессия (модули OFF) — критично

- [ ] `/start` новым юзером → регистрация как раньше, никаких шагов оплаты/согласий/новых вопросов.
- [ ] Существующий (из ~590) юзер → данные на месте, статус не изменился.
- [ ] `init_db()` дважды (перезапуск) → без ошибок, без потери данных. `payment_status` у старых = `not_paid`.
- [ ] `/admin → ⚙️ Настройки` показывает новые строки модулей/настроек без ошибок.
- [ ] «📋 Заявки» работают как прежде (миграция REG_FLOW на 3-кортежи ничего не сломала).
- [ ] Прогнать автотесты: `pytest tests/` → **98 passed**.

## B. Админ-настройка (общая, оба события)

- [ ] «🎭 Тип события»: `conference` → оплата+согласия Вкл; `forum` → оба Выкл; `custom` → без изменений.
- [ ] Тумблеры «💳 Оплата» / «📋 Согласия» переключаются, состояние видно в тексте настроек.
- [ ] «📋 Вопросы регистрации» — в списке появились новые: 🎂 Дата рождения, 🎯 Направление обучения, 🎯 Цель участия, 📋 Форматы форума, 🧡 Амбассадор, 📅 Дата приезда (все по умолчанию ❌).
- [ ] Редактируемые списки опций (по строке, «-» = скрыть): 🏙 Города, 🎯 Направления обучения, 🎯 Цели участия, 📋 Форматы форума, 🏫 База ВУЗов.
- [ ] «🏫 Режим ВУЗа»: `list` / `text`. «🎓 Условный блок ВУЗа»: `on` / `off`.
- [ ] «✏️ Тексты вопросов»: переопредели текст вопроса → участник видит новый; «-» возвращает стандартный (✅/✏️ метка в списке).
- [ ] Не-админ дёргает любой admin-callback → «Недостаточно прав».

# C. YOULEAD (форум) — сценарий

Профиль: полная форма, **предотбор** (preselect), **согласия ON + PDF**, оплата обычно **OFF**
(бесплатно), вопросный набор YL'26, тексты «заявка принята / отбор пройден / не пройден» свои.

## C1. Настройка YL'26 (0 хардкода)

- [ ] `Тип события = forum`, затем вручную «📋 Согласия = Вкл».
- [ ] «📋 Список согласий»: `Согласие на обработку ПД|data` + `Политика конфиденциальности|policy`.
- [ ] «🧾 PDF согласий» → по кнопке на каждый пункт прислать PDF → пометка ✅. (Скачать GDrive-PDF, отправить боту.)
- [ ] Включить вопросы YL'26: Дата рождения, Цель участия, Форматы форума, Направление обучения, Амбассадор; источник/город/ВУЗ/курс по необходимости.
- [ ] «🏫 Режим ВУЗа = list», «🏫 База ВУЗов» заполнена; ИЛИ режим `text` (свободный ввод).
- [ ] «🎓 Условный блок ВУЗа = off» (на YL образование — уровень, ВУЗ/курс спрашиваем всегда).
- [ ] Заполнить «🏙 Города», «🎯 Направления обучения», «🎯 Цели участия», «📋 Форматы форума», «📢 Источники» под тексты YL'26.
- [ ] Тексты: «✅ После регистрации» (заявка принята), «reject_text» (отбор не пройден), приветствие-одобрения (отбор пройден).

## C2. Юзер: прохождение формы YL'26

- [ ] `/start` → ФИО → возраст → **🎂 дата рождения**: `abc` отклоняется, `01.01.2000` принимается.
- [ ] **🏙 Город**: кнопки из списка + «Другое» (свой текст) + «Пропустить».
- [ ] **🎓 Образование**: выбор; при `edu_conditional=off` ВУЗ/курс/направление спрашиваются независимо.
- [ ] **🏫 ВУЗ**: режим `list` — выбор из базы + «Другое»; режим `text` — свободный ввод.
- [ ] **🎯 Направление обучения**: выбор из настроенного списка + «Другое».
- [ ] **🎯 Цель участия (мультивыбор)**: inline-кнопки с ▫️/✅, отметить несколько, «Готово ▶️». Текстом не пропустить (просит кнопки). Пустой выбор → «Выбери хотя бы один».
- [ ] **📋 Форматы форума (мультивыбор)**: аналогично.
- [ ] **🧡 Амбассадор**: «Да!» / «Пока нет» → сохраняется в `is_ambassador_candidate`.
- [ ] **📄 Резюме**: PDF/DOCX (если включено).
- [ ] **Согласия** (в конце, до резюме итога): по карточке на пункт, PDF прикреплён, «✅ Принимаю» обязательно, текстом не пропустить.
- [ ] Итоговое резюме показывает новые поля (дата рождения, направление, цель, форматы, амбассадор).

## C3. Предотбор + тексты (YL)

- [ ] `preselect_enabled=on`, юзер вне allowlist без @username → просьба задать username.
- [ ] Юзер не прошёл отбор → текст «отбор не пройден» (+ ссылка, если задана).
- [ ] Заявка принята (pending) → текст «заявка принята».
- [ ] Одобрение менеджером → текст «отбор пройден» + меню.
- [ ] АДМИН-проверка БД: согласия записаны в `user_consents`; мультивыбор сохранён CSV в `goal`/`formats`.

# D. SUMMIT (конференция / RusCo) — сценарий

Профиль: **оплата ON**, варианты/реквизиты/дедлайн/штрафы, чек + очередь + напоминания,
conference-вопросы (департамент, роль AIESEC, приезд, проживание и т.п.), согласия опционально.

## D1. Настройка Summit

- [ ] `Тип события = conference` → оплата+согласия Вкл (далее правим вручную при нужде).
- [ ] «💳 Варианты оплаты»: один (`Полный билет|5000`) и мульти (несколько строк, в т.ч. `0`).
- [ ] «💰 Реквизиты», «📅 Дедлайн оплаты» (`ДД.ММ.ГГГГ ЧЧ:ММ`), «⚠️ Штрафы за отмену».
- [ ] Включить conference-вопросы (департамент / роль AIESEC / приезд / проживание / cc-shop / англ. и т.д.).

## D2. Юзер: оплата после одобрения (PAY-02/03)

- [ ] Мульти-варианты → «💳 Выбери вариант участия» с кнопками → тап → детали (вариант, сумма, реквизиты, дедлайн, штрафы) + просьба чек.
- [ ] Один/бесплатный вариант → выбор пропускается, сразу детали.
- [ ] Чек **PDF** → принят, статус `receipt_sent`.
- [ ] Чек **фото/скрин** → принят (макс. разрешение).
- [ ] **DOCX/ZIP** → «только PDF…», остаётся на шаге. **Текст/стикер** → «PDF или скриншот…».
- [ ] При оплате ON обычное приветствие НЕ приходит — меню только после подтверждения чека.

## D3. Админ: очередь чеков (PAY-04) «🧾 Чеки»

- [ ] Пусто → «✅ Чеков на проверке нет».
- [ ] Карточка: имя, вариант, признак чека; кнопки Подтвердить / Отклонить / 🧾 Чек / ⏭ Следующий.
- [ ] «🧾 Чек» → присылается файл (PDF — документом, скрин — фото).
- [ ] «✅ Подтвердить» → `paid`; юзеру «Оплата подтверждена!» **с меню**; очередь сдвигается.
- [ ] Двойное подтверждение → «Чек уже обработан» (rowcount-гард).
- [ ] «❌ Отклонить» + причина → `not_paid`, юзеру причина + «загрузи повторно». Причина «-» → без текста.
- [ ] «⏭ Следующий» → скрывает из сессии. Повторная загрузка чека → снова в очереди.

## D4. Напоминания об оплате (PAY-06)

> Для проверки задай дедлайн так, чтобы `−3д`/`−1д` были через 1–2 мин, загрузи чек.

- [ ] После загрузки чека регистрируются `pay_reminder_<uid>_minus3d/minus1d` (если точки в будущем).
- [ ] Напоминание НЕ приходит при `paid`/`receipt_sent` (SC#5).
- [ ] После «Подтвердить» напоминания отменяются.
- [ ] Перезапуск бота → задания восстановлены из `data/jobs.sqlite`.
- [ ] Overdue-sweep: после дедлайна `not_paid` → `overdue`; `receipt_sent`/`paid` не трогаются.

## E. Универсальные механики (проверить раз, не зависят от события)

- [ ] **Мультивыбор**: тогглы ▫️/✅ переключаются (edit_reply_markup), «Готово» сохраняет CSV, повторное нажатие снимает отметку.
- [ ] **Согласие — идемпотентность**: повторный «Принимаю» не падает (INSERT OR IGNORE).
- [ ] **Consent PDF UI**: при пустом «Списке согласий» раздел просит сперва заполнить список; не-PDF в загрузку согласия → отказ.
- [ ] **Оба модуля + полная форма**: форма → согласия → одобрение → оплата → чек → подтверждение → меню (сквозной путь).
- [ ] **Пустые списки при включённых модулях**: бот не падает (оплата = единый бесплатный путь; согласий 0 шагов; мультивыбор без опций — дефолты-сид).
