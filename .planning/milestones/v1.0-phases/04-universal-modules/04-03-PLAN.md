## Phase Goal

**As a** DXP manager, **I want to** toggle consent and payment modules in the admin panel and have them activate immediately for new registrations, **so that** the bot works for both free forums and paid conferences without redeploying code.

**Decisions covered:** D-01 (consent list rendered per item), D-03 (each consent its own «Принимаю» step), D-04 (consent PDF attachment), D-07 (REG_FLOW typed steps: text/date/consent), D-14 (Slice 1 = modularity + consent), D-15 (consent steps absent when toggle OFF).

<objective>
Extend the registration flow with typed REG_FLOW steps: (1) migrate REG_FLOW to 3-tuples with a `type` field (date / text / consent) keeping all existing 2-tuple steps working via star-unpack, (2) add a `date` step type with ДД.ММ.ГГГГ validation, and (3) add the consent module — injecting consent steps from the consent_list setting at the end of the flow when consent_enabled=on.

Purpose: Delivers ROADMAP SC#2: "User completing registration with consent module enabled must tap Принимаю for each configured consent item before the form finalizes; skipping any consent is not possible." Also delivers MOD-02 (date field type) and MOD-03 (consent step type).

Output: handlers/registration.py with typed REG_FLOW, date step handler, consent step injection in _get_enabled_steps, _ask_step branch for consent steps, consent_accept callback that writes to user_consents and advances the flow.
</objective>
