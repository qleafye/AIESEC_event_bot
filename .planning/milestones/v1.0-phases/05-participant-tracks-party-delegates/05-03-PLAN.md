## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram callback → admin handler | callback_data is client-supplied; any user can send an arbitrary callback to the bot |
| registrant-controlled DB text → admin message | full_name and participant_type render into an HTML-parsed admin message |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03-01 | Elevation of Privilege | `reg_q_ptoggle:` / `reg_q_track:` / party preset handlers | mitigate | Every new callback handler opens with the `callback.from_user.id not in config.ADMIN_IDS` re-check plus `show_alert` denial, matching `_toggle_module_setting`. A non-admin sending a crafted callback cannot write a setting. |
| T-05-03-02 | Tampering | `reg_q_ptoggle:{setting_key}` payload | mitigate | The setting_key taken from callback_data must be validated against the setting_keys present in `REG_FLOW` before being suffixed and written; an unknown key is rejected with a callback answer.
