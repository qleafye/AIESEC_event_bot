## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02-01 | Elevation of Privilege | toggle_payment_enabled / toggle_consent_enabled callbacks | mitigate | _toggle_module_setting checks config.ADMIN_IDS on every call before reading or writing any setting. Pattern copied verbatim from _toggle_approval_setting (admin.py:483 precedent). |
| T-04-02-02 | Elevation of Privilege | _apply_event_type_preset (called from settings_edit_value) | mitigate | settings_edit_value is already gated by is_admin filter (line ~747); _apply_event_type_preset is a private function only callable from that gated handler. |
| T-04-02-03 | Tampering | event_type preset writes payment_enabled + consent_enabled | accept | If the preset is interrupted (e.g., bot crash mid-write), the worst case is one flag written and one not — no user data corrupted. Default-OFF posture means partial state (e.g., payment=on but consent=off) is safe: each module checks its own flag independently. Admin can manually correct via toggle buttons. |
| T-04-02-04 | Denial of Service | payment_enabled / consent_enabled accidentally set to "on" for live YL'26 | mitigate | Default is OFF (absent key → treated as off per D-15 fail-safe). Both modules default to off when the setting key does not exist in bot_settings. Admin must deliberately tap the toggle to enable. |
</threat_model>
