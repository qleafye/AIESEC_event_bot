## Phase Goal

**As a** party-team organizer, **I want to** open a dedicated worksheet tab containing only party guests and only the columns that apply to them, **so that** I can work the door list without scrolling past empty university and resume columns.

**Decisions covered:** D-11 (separate tab with its own header), D-12 (party rows go to the party tab only, never duplicated on the main sheet).

<objective>
Add incremental per-row append to a second, admin-named Google Sheets worksheet, and route party registrations there exclusively.

Purpose: this is the one genuinely new piece of infrastructure in Phase 5. `append_to_sheet` is hardcoded to a single cached worksheet and `sync_named_worksheet` is full-overwrite only — neither shape fits an incremental append to a second tab.

Output: four generalized functions in `services/sheets.py`, the party column set and routing in `handlers/registration.py`, a gated startup header call in `main.py`, `tests/test_sheets_phase5.py`, and a final end-to-end human verification of the whole phase.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| registrant free text → Google Sheets cell | Registrant-supplied strings are written into a spreadsheet that organizers open and interact with |
| bot → Google Sheets API | Outbound network dependency on a third party, in the registration completion path |
| `party_sheet_tab` setting → worksheet targeting | An admin-supplied string selects/creates a worksheet |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-06-01 | Injection | `party_sheet_row` cell values | mitigate | Every registrant-supplied cell passes through `database.db._csv_safe`, which prefixes `'` on values starting with `= + - @ \t \r`, so a crafted ФИО cannot execute as a formula when an organizer opens the tab. Reuses the reviewed implementation from 260713-jgi rather than a second copy. |
| T-05-06-02 | Denial of Service | Sheets API in the finalize path | mitigate | The append is fire-and-forget via an asyncio task inside a try/except, with the retry/backoff loop bounded by `MAX_RETRIES`. Sheets being down or rate-limited degrades to a missing spreadsheet row, never a failed or blocked registration. |
| T-05-06-03 | Information Disclosure | party sheet logging | mitigate | The append logger emits only the telegram_id element and the tab name, never the full row — the row contains phone numbers and allergy data. Matches the PII-safe logging convention at sheets.py:125. |
| T-05-06-04 | Information Disclosure | wrong-tab write | mitigate | D-12 exclusivity is enforced by an if/else with exactly one append scheduled per registration, and verified by a grep assertion that the party branch never calls `append_to_sheet`. A party guest's data cannot leak onto the tab the full-delegate team works from, and vice versa. |
| T-05-06-05 | Tampering | `party_sheet_tab` setting value | mitigate | The tab name is admin-only (written through the admin settings editor added in 05-03, which re-checks ADMIN_IDS) and is used solely as a worksheet title passed to gspread — it is never interpolated into a query or a range expression. |
| T-05-06-06 | Denial of Service | unbounded tab auto-creation | accept | `_get_named_sheet` auto-creates a missing tab. Only two named tabs are ever requested (party, allowlist) and the name is admin-controlled, so no user action can cause repeated worksheet creation. Risk accepted. |
</threat_model>
