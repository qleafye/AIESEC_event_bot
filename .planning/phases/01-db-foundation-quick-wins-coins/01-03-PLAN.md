<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin → /coins | admin-supplied username, amount, and free-text reason cross into the ledger |
| any user → leaderboard/balance | user identity drives which balance/rank is shown |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Elevation | /coins authorization | mitigate | Handler guarded by `is_admin` (checks `from_user.id in config.ADMIN_IDS`) — not the spoofable @username. Verified by structural test asserting is_admin on the decorator. |
| T-03-02 | Injection | username lookup + reason | mitigate | Username lookup reuses parameterized `get_user_by_username`; reason is passed as a `?` bind param to add_coins (db.py), never interpolated. Amount is integer-parsed via `_parse_coins_amount`, rejecting non-numeric input. |
| T-03-03 | Injection (stored XSS-style) | reason/name display | mitigate | All user/admin-supplied strings rendered to Telegram HTML are html.escaped in `render_leaderboard` and the /coins confirmation. |
| T-03-04 | Tampering | balance manipulation | mitigate | Balance is a derived SUM(delta) over the append-only ledger (Plan 01); /coins only INSERTs ledger rows (credit or debit), never edits a stored balance. Negative balances are an accepted design decision (D-14), not a vulnerability. |
</threat_model>
