Create a standalone one-shot script matching the style of scripts/diag_sheet_columns.py
(module docstring with run instructions at the top, `async def main()`, `asyncio.run(main())`
guard, direct imports from config / database.db / services.nextcloud). Import config as
`from config import config`, `import database.db` (or `from database.db import init_db`),
`from services.nextcloud import upload_resume`, plus `aiosqlite`, `asyncio`, `argparse`,
`logging`.

Structure:

1. `async def select_pending_resumes(db) -> list` — takes an ALREADY-OPEN aiosqlite
   connection. Runs:
   `SELECT telegram_id, resume_file_id FROM users WHERE resume_file_id IS NOT NULL AND resume_file_id != '' AND (resume_url IS NULL OR resume_url = '')`
   and returns the rows as a list of (telegram_id, resume_file_id) tuples
   (e.g. `rows = await db.execute_fetchall(...)` or cursor + fetchall). This helper MUST be
   importable and callable without a Bot — it only touches the connection passed in.

2. `def _parse_args()` — argparse with `--dry-run` (store_true) and
   `--limit` (type=int, default=0; 0/None = all).

3. `async def main()`:
   - `await init_db()` first (idempotent — guarantees the resume_url column exists).
   - Guard: `if not config.NEXTCLOUD_BASE_URL:` print
     "Nextcloud не настроен (NEXTCLOUD_BASE_URL пуст) — заливать некуда, выход" and `return`
     WITHOUT constructing the bot or opening any network/session.
   - Open the DB: `async with aiosqlite.connect(config.DB_PATH) as db:` and call
     `candidates = await select_pending_resumes(db)`. Apply `--limit` if > 0
     (`candidates = candidates[:limit]`).
   - **--dry-run path:** for each candidate just print its telegram_id ("WOULD process
     {telegram_id}"), then print the summary, and return — NO bot, NO network, NO writes.
   - **Real path:** build the Bot by copying main.py EXACTLY (default = DefaultBotProperties(
     parse_mode=ParseMode.HTML); session = AiohttpSession(proxy=config.PROXY_URL.get_secret_value())
     if config.PROXY_URL else None; bot = Bot(token=config.BOT_TOKEN.get_secret_value(),
     default=default, session=session)). Wrap the processing in try/finally with
     `await bot.session.close()` in the finally.
   - Per-user loop (counts: success, failed): wrap EACH user in try/except so one failure
     logs (`logging.exception` / print which telegram_id) and increments `failed`, then
     `continue` — the batch never aborts.
       * Derive filename: try `f = await bot.get_file(file_id)`; take the extension from
         `f.file_path` via `os.path.splitext(f.file_path)[1]` → `filename = f"resume_{telegram_id}{ext}"`.
         On ANY exception (file deleted on Telegram side → 400), fall back to
         `filename = "resume"`. This get_file call is OUTSIDE upload_resume so it MUST be
         wrapped here.
       * `url = await upload_resume(bot, resume_file_id, filename)`.
       * If `url` truthy → `UPDATE users SET resume_url=? WHERE telegram_id=?` on the open
         `db` connection, `await db.commit()`, increment success.
       * If `url` is None → increment failed, log which telegram_id.
       * `await asyncio.sleep(0.5)` between iterations.
   - Summary (both paths): print total candidates, success, failed, and the reminder:
     "Готово. Резюме залиты в БД (resume_url). Чтобы колонка «Резюме (ссылка)» заполнилась
     в Google-таблице — нажми в админке кнопку «Пересобрать таблицу»."

The script writes ONLY to the DB (resume_url) — it MUST NOT import or call anything from
services.sheets and MUST NOT start bot polling. Add `import os` for splitext.
  </action>
