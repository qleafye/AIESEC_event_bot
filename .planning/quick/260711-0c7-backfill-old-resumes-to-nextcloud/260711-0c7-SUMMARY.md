# Quick 260711-0c7: Backfill Old Resumes to Nextcloud Summary

One-off maintenance CLI that re-uploads pre-Nextcloud delegates' Telegram resume files to Nextcloud and writes the resulting share URL into `users.resume_url`, fully fail-soft per user.

## What Was Built

- `scripts/backfill_resumes.py` — standalone `python -m scripts.backfill_resumes` script:
  - `select_pending_resumes(db)` — Bot-free helper selecting `(telegram_id, resume_file_id)` for rows with a `resume_file_id` but empty `resume_url`.
  - `main()` — calls idempotent `init_db()`, exits early with a Russian message when `NEXTCLOUD_BASE_URL` is empty (no Bot/network), otherwise builds the Bot exactly like `main.py`, loops candidates with per-user `try/except continue`, derives the filename via `bot.get_file` (with `"resume"` fallback), calls `upload_resume`, and writes `UPDATE users SET resume_url=?` on success.
  - `--dry-run` prints `WOULD process {id}` per candidate with no network/writes; `--limit N` caps processing.
  - `await bot.session.close()` in a `finally`; ends with the «Пересобрать таблицу» reminder.
- `tests/test_backfill_resumes.py` — `test_select_pending_resumes_picks_only_missing` seeds file+no-url (picked), file+url (skipped), no-file (skipped); asserts exactly one row (`telegram_id=1`, `FILE_A`). Imports the helper without a Bot.
