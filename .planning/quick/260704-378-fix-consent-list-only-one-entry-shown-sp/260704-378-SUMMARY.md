# Summary — Consent list `;` separator

## What changed

Both consent parsers now split on `;` as well as newlines, so a multi-line
consent list entered on one line (`Label|key; Label2|key2`) parses into multiple
consents. This works around the Telegram mobile Enter=send trap that caused only
the first consent line to be saved (→ only 1 consent shown in the PDF panel and
in registration).

- `handlers/registration.py:_consent_entries` — `raw.replace(";", "\n")` before splitlines.
- `handlers/admin.py:_parse_consent_list` — same.
- `handlers/admin.py` SETTINGS_FIELDS `consent_list` help text — documents the `;` option with an example.

Backward compatible: existing newline-separated `consent_list` values parse
unchanged.

## Verification

- `pytest tests/test_registration_phase4.py` → 17 passed.
- Parse spot-check: newline / semicolon / mixed / single / legacy inputs all
  produce the expected entry lists.

## Notes

Root cause is a data/UX trap, not a parser bug — the parsers were already
correct for multi-line input. If an admin's stored `consent_list` already lost
lines, they must re-enter it (now possible on one line via `;`).
