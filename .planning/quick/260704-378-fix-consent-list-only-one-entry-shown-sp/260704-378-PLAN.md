# Quick 260704-378: Consent list shows only 1 entry — accept `;` separator

## Problem

Admin reports the consent system shows only one consent everywhere: one inline
button in «🧾 PDF согласий» and one consent step during registration. Both places
read the same `consent_list` setting and parse it identically (split on lines) —
`_parse_consent_list` (handlers/admin.py) and `_consent_entries`
(handlers/registration.py). The parsers are correct for multi-line input (test
covers it), so the stored value contains only one valid line.

Root cause: `consent_list` is saved from a single Telegram message via
`settings_edit_value` → `set_setting` (full overwrite). On mobile Telegram with
Enter=send, typing each consent on its own line sends the message after the first
line — only that first line is stored. Multi-line entry is unreliable on mobile.

## Fix

Accept `;` as an entry separator in addition to newlines. Admins hit by the
Enter=send trap can enter all consents on one line: `Label|key; Label2|key2`.
Implemented as `raw.replace(";", "\n")` before `splitlines()` in both parsers —
zero behavior change for existing newline data.

## Tasks

1. `handlers/registration.py` `_consent_entries`: `.replace(";", "\n")` before splitlines.
2. `handlers/admin.py` `_parse_consent_list`: same.
3. `handlers/admin.py` SETTINGS_FIELDS `consent_list` help text: document the `;` option.

## Verify

- `pytest tests/test_registration_phase4.py` green (17 passed).
- Manual parse check: newline, semicolon, mixed, and legacy inputs all yield the
  expected multi-entry lists.
