  <name>Task 1 (CR-1): Page the moderation + receipt queues by offset so skips past 50 don't false-empty</name>
  <files>handlers/admin.py, database/db.py, tests/test_review_b1b.py</files>
  <action>
Fix both tinder queues so they page forward instead of re-fetching the same oldest 50.

1. In database/db.py, add an `offset: int = 0` parameter to `get_receipt_pending_users`
   (mirror the signature `get_pending_users` already has) and append `OFFSET ?` to its SQL,
   binding `(limit, offset)`. Keep default behavior identical (`offset=0`).
   `get_pending_users` already supports offset — leave it.

2. In `_show_current_card` (handlers/admin.py ~:2204), replace the single
   `get_pending_users(limit=50)` fetch with a loop that pages until it finds the first
   non-skipped card OR exhausts the queue: read `skipped` and `total = get_pending_count()`,
   then `offset=0; visible=[]; while not visible and offset < total: batch = await
   get_pending_users(limit=50, offset=offset); if not batch: break; visible = [u for u in
   batch if u['telegram_id'] not in skipped]; offset += len(batch)`. Keep the existing
   "✅ Заявок нет." branch, `current = visible[0]`, and `position = total - <remaining
   non-skipped> + 1` semantics. Preserve exact behavior for <50 items (single-iteration loop).

3. Apply the identical change to `_show_current_receipt_card` (~:2438) using
   `get_receipt_pending_users(limit=50, offset=offset)` and `rcpt_skipped` /
   `get_receipt_pending_count()`.

Do not change DB status on skip (skip stays session-local, as designed). Must not double-show
or skip a card: paging strictly advances `offset` by the actual batch length.

4. Add tests to tests/test_review_b1b.py (create the file) using `tmp_path` + `asyncio.run`
   against a temp DB (follow tests/test_db_phase4.py conventions): insert 60 pending users;
   assert `get_pending_users(limit=50, offset=50)` returns the 10 that the un-offset fetch
   never reached, with no overlap vs `offset=0`; assert `get_receipt_pending_users(limit=50,
   offset=50)` likewise pages the receipt queue. (These pin the DB paging the handler now
   relies on; the handler loop is exercised by the paging guarantee + the manual UAT below.)
  </action>
  <verify>
    <automated>python -m pytest tests/test_review_b1b.py -k "paging or offset" -q</automated>
  </verify>
  <done>get_receipt_pending_users accepts offset; both card renderers page forward and never report empty while pending rows remain past the first 50; new paging tests pass; <50-item behavior unchanged.</done>

<task type="auto">
  <name>Task 3 (CR-8): Robust ASCII-int parsing at both sites + register a global aiogram error handler</name>
  <files>handlers/registration.py, main.py, tests/test_review_b1b.py</files>
  <action>
Two parts.

(a) Numeric parsing — stop trusting `str.isdigit()` (accepts Unicode digits like ²/① that
crash `int()`):
  - `_extract_referrer_id` (~:686): replace `if not arg.isdigit(): return None; referrer_id =
    int(arg)` with a `try: referrer_id = int(arg) except ValueError: return None`. Keep the
    self-referral guard (`referrer_id == current_user_id -> None`). (`int()` already tolerates
    surrounding behavior; ASCII-only is enforced by the except.)
  - `process_age` (~:1360): replace `if not raw_age.isdigit(): ...` with `try: age =
    int(raw_age) except ValueError: await message.answer("Возраст должен быть числом.
    Попробуй еще раз."); return`. Keep the 10..120 range check afterward.
  - Note: if the reviewer/executor prefers an explicit `str.isascii() and str.isdigit()`
    guard, that is acceptable too — but try/except int is the canonical robust form and
    matches _parse_rcpt/_parse_appr elsewhere in the codebase.

(b) Global error handler — none exists, so any unhandled exception silently drops the update.
  In main.py, register an aiogram v3 error handler on the dispatcher. Add an async handler
  decorated `@dp.errors()` (or `dp.errors.register(...)`) that receives the
  `ErrorEvent`, logs `event.exception` WITH context (`event.update`) at ERROR level via the
  module logger, and returns `True` (handled) so the failure is visible in logs and fails
  soft rather than propagating. Wire it after `dp = Dispatcher(...)` and before
  `start_polling`. Use aiogram 3.29's actual API (import `ErrorEvent` from `aiogram.types`;
  the decorator is `@dp.errors()`). Do not swallow KeyboardInterrupt/SystemExit.

(c) Tests in tests/test_review_b1b.py: `_extract_referrer_id("²", 999) is None`;
  `_extract_referrer_id("①", 999) is None`; `_extract_referrer_id("123", 999) == 123`;
  `_extract_referrer_id("123", 123) is None` (self-ref); `_extract_referrer_id("abc", 1) is
  None`. For age, test the pure predicate: assert `int("²")` raising is now handled by the
  parse path — simplest is to factor the age validation into a tiny helper
  `_parse_age(raw) -> int | None` returning None for non-ASCII-digit / out-of-range, and unit
  test it (`_parse_age("²") is None`, `_parse_age("25") == 25`, `_parse_age("5") is None`,
  `_parse_age("200") is None`); `process_age` then calls it. (This keeps the crash class
  unit-tested without mocking the FSM.)
  </action>

<task type="auto">
  <name>Task 4 (CR-9): Freeze the active sheet schema so mid-event toggles don't misalign rows vs header</name>
  <files>handlers/registration.py, main.py, handlers/admin.py, tests/test_review_b1b.py</files>
  <action>
Make each registration's row align to the physical header actually on the sheet, instead of
recomputing gate state live per registration.

Approach (matches the existing "only-enabled-columns, header written once, rebuild is the
re-sync point" design — chosen over full-static-schema so the sheet width still follows the
event preset; migration-safe because it only adds a bot_settings KV key, no DB schema change):

1. In handlers/registration.py add two helpers backed by bot_settings:
   - `async def set_sheet_schema(headers: list[str]) -> None`: `await
     set_setting("sheet_header_schema", json.dumps(headers))`.
   - `async def get_sheet_schema() -> list[str]`: read `"sheet_header_schema"`; if present,
     `json.loads` it; if absent/blank/malformed, FALL BACK to `await active_sheet_headers()`
     (this preserves current behavior for existing deployments that have no snapshot yet —
     zero migration risk).

2. Change `active_sheet_row(data)` (~:844) to project against the FROZEN schema:
   `headers = await get_sheet_schema(); values = _sheet_value_map(data); return
   [values.get(h, "-") for h in headers]`. (Name-based projection already; only the header
   source changes from live to frozen.)

3. Persist the snapshot at every point the physical header is (re)written, so snapshot ==
   what's on the sheet:
   - main.py startup (~:59): compute `_hdrs = await active_sheet_headers()` once, then
     `await set_sheet_schema(_hdrs)` and `asyncio.create_task(ensure_sheet_header(_hdrs))`
     (persist BEFORE/with the header write; keep it fail-soft — wrap in try/except so a
     bot_settings hiccup never blocks startup).
   - handlers/admin.py rebuild (~:821): after `headers = await active_sheet_headers()` and a
     successful `rebuild_main_sheet(headers, rows)`, call `await set_sheet_schema(headers)` so
     the rebuilt physical header and the frozen snapshot move together. (Rebuild remains the
     explicit re-sync action the admin uses after changing the event preset.)

4. Tests in tests/test_review_b1b.py (tmp_path DB, follow test_registration_phase4.py's
   `active_sheet_headers` test): enable all questions, `set_sheet_schema(await
   active_sheet_headers())`; then toggle ONE question OFF (set its `reg_q_*` to a disabled
   value) and assert `active_sheet_row(data)` STILL returns a row whose width == the frozen
   schema width (not the reduced live width) and whose values remain aligned to the frozen
   headers. Also assert `get_sheet_schema()` returns the frozen list even after the toggle,
   and that with NO snapshot set it falls back to live `active_sheet_headers()` (== current
   behavior).
  </action>
