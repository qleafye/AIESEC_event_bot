# Quick 260702-vr1: Fix payment receipt-upload trap + "pay later" + "upload receipt" menu entry

## Problem

While in FSM state `Registration.receipt_upload`, the catch-all handler
`handlers/payment.py:194` matches **every** message (no command filter). Because
`payment.router` is included **before** `registration.router` (main.py:50 vs 51),
`/start` (registered in registration with `StateFilter("*")`) never reaches
`cmd_start`. The user is trapped in the payment window with no escape and no way
to defer payment and upload the receipt later.

## Approach

1. **Escape hatch** — exclude commands from the receipt catch-all so `/start`
   (and `/cancel`) fall through to their real handlers.
2. **"Pay later" button** — inline `⏭ Оплачу позже` on both the option picker and
   the requisites/details message; clears FSM state, drops the user on the main menu.
   DB `payment_status` stays `not_paid`.
3. **Re-entry point** — persistent reply-keyboard button `💳 Загрузить чек`, shown
   only while the user still owes a receipt. Gated on **DB status** (survives the
   MemoryStorage FSM reset on restart), not on FSM state.

Predicate `should_offer_receipt_upload(telegram_id)`: `payment_enabled == on`
AND `payment_status in {not_paid, overdue}` AND resolved requisites are non-empty
(so free/no-requisites participants never see the button).

## Tasks

### Task 1 — payment.py: escape, pay-later, re-entry predicate
- `handlers/payment.py`
- Catch-all `process_receipt_invalid`: add `~F.text.startswith("/")`; update copy to
  mention `/start`.
- Add `_PAY_LATER_BTN` + `should_offer_receipt_upload()`.
- Option picker (`start_payment_step`) and details (`_show_payment_details`): append
  the pay-later inline button.
- Add `process_pay_later` callback: clear state, send main menu (with telegram_id).
- verify: `python -c "import handlers.payment"`
- done: catch-all ignores `/start`; both payment surfaces show pay-later; predicate importable.

### Task 2 — main menu button plumbing
- `keyboards/builders.py`: `get_main_menu_kb(telegram_id: int | None = None)` — when id
  given and `should_offer_receipt_upload` is true, append `💳 Загрузить чек` (lazy import,
  fail-soft). Update all call sites to pass the user's id.
- `handlers/user_actions.py`: handler for `💳 Загрузить чек` → `ensure_registered` →
  guard on predicate → `start_payment_step`.
- verify: `python -c "import keyboards.builders, handlers.user_actions"`
- done: returning unpaid user sees the button; tapping it re-opens the payment step; button
  gone once `receipt_sent`/`paid`.
