# Phase quick-260711-16c Plan 01: Resume links via one folder-share deep-link Summary

Redesigned resume sharing: the bot no longer creates per-file OCS public shares. It now WebDAV-PUTs each resume (file OR text) into a Nextcloud `resumes` folder and stores a deep-link into ONE manually-created public folder share (`/s/<token>/download?path=%2F&files=<name>`). Files are named `<ФИО>_<username|telegram_id>` with the original extension (text resumes become `.txt`). Everything stays fail-soft — registration never blocks or breaks on a Nextcloud outage.

## What Changed

- **services/nextcloud.py** — Removed the entire OCS `/shares` POST path and all `NEXTCLOUD_SHARE_PASSWORD` reads. Added `_put_bytes()` (WebDAV PUT), `_file_link()` (deep-link builder), rewrote `upload_resume()`, and added `upload_text_resume()` (no Bot needed). Both entrypoints guard on WEBDAV_URL/PUBLIC_URL/FOLDER_SHARE_TOKEN and are fully fail-soft (try/except → None).
- **config.py** — Added `NEXTCLOUD_PUBLIC_URL` and `NEXTCLOUD_FOLDER_SHARE_TOKEN`. Kept `NEXTCLOUD_SHARE_PASSWORD` as a field (marked compat-only; no longer read).
- **handlers/registration.py** — Imported `upload_text_resume`; added `_resume_person_name(data)` helper (`ФИО_username|id`, strips leading `@`, treats `-`/empty as missing → telegram_id). Rewrote the finalize upload block into file/text branches, each under `asyncio.wait_for(..., timeout=20)` and a shared fail-soft try/except before `add_user`.
- **scripts/backfill_resumes.py** — `select_pending_resumes` now returns 5 columns and picks BOTH file- and text-resumes lacking a `resume_url`. Guard switched to WEBDAV/PUBLIC/TOKEN. Dry-run prints the resume type; the real loop uploads via `upload_resume` (file) or `upload_text_resume` (text) using the shared `_resume_person_name` naming.
- **.env.example** — Added `NEXTCLOUD_PUBLIC_URL` and `NEXTCLOUD_FOLDER_SHARE_TOKEN` with the folder-share model explanation; marked `NEXTCLOUD_SHARE_PASSWORD` deprecated (code no longer sends it).
- **tests** — Added `_file_link` deep-link assertion, `upload_text_resume` disabled-guard test, updated the disabled/fail-soft guard to require all three config keys; backfill test now covers 5 columns and a new text-resume PICKED case.

## Notes / Follow-ups

- Old `resume_url` values (per-file `/s/...` links from earlier testing) are NOT overwritten by backfill — the SELECT only picks rows where `resume_url` is NULL/empty. To re-link them to the new deep-link format, clear them manually (`UPDATE users SET resume_url='' WHERE ...`) and re-run the backfill.
- The deep-link format lives entirely in `_file_link()`, so switching `download` → in-browser preview is a one-line change.
- Nextcloud will prompt for the folder-share password once per browser session, then serve files directly.
