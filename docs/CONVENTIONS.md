# Конвенции проекта

Здесь фиксируются практические правила, выведенные из реальных инцидентов и рефакторов —
не теория, а то, что уже один раз сработало или сломалось. Формулировки — для человека
(«бот для людей», см. CLAUDE.md): без жаргона там, где можно объяснить по-русски.

## Размер модуля: ориентир ~800 строк

**Правило.** `handlers/*.py` (и по аналогии любой другой модуль с обработчиками/бизнес-логикой)
не должен разрастаться дальше ~800 строк. Модуль, который приближается к порогу — сигнал
разрезать его по шву фичи/префикса callback'ов, а не дописывать очередной блок в конец.

**Почему именно этот порог.** Phase 13 (REFAC) разрезала `handlers/admin.py` (3067 строк) и
`handlers/registration.py` (2953 строки) — оба на момент начала рефактора были нечитаемыми
god-файлами: правку одной кнопки нельзя было сделать без риска задеть двадцать несвязанных
экранов в той же вкладке редактора. ~800 строк — эмпирический ориентир по итогу этого
рефактора: сиамы (`admin_cities.py`, `admin_broadcasts.py`, `admin_roles.py`, ...), уложенные
в этот размер, остаются такими, что один файл = одна связная область экрана.

**Технический приём разреза (закреплён этой фазой).** Один общий `Router()` на god-файл,
определённый в модуле-агрегаторе; файлы-«швы» ничего не создают заново, а импортируют этот
`router` и декорируют его напрямую (`from handlers.admin import router`). Агрегатор подключает
швы **импортами в самом низу файла**, каждый отдельной строкой, **в том порядке, в котором
их обработчики стояли в исходном god-файле**. Это критично: порядок регистрации хендлеров в
aiogram — это порядок вызова `@router.<event>()` во время импорта модуля, а Python исполняет
импорты по порядку строк. Переставить импорты швов местами или объединить их в один
`import`-стейтмент с несколькими модулями — значит незаметно поменять порядок маршрутизации
(в aiogram это первый совпавший фильтр побеждает — реордер меняет ПОВЕДЕНИЕ, не только косметику
файла). `main.py` при этом не трогается: `router` — тот же объект, что и был, подключён туда же
ровно один раз, значит middleware тоже накручивается один раз.

Альтернатива (свой `Router()` на каждый шов + `include_router` в `main.py`) была рассмотрена
и отклонена (см. `13-CONTEXT.md`, открытый вопрос №2) — она требует трогать `main.py` и повышает
риск случайно переставить порядок `include_router(...)`, а значит и порядок обработки апдейтов
между роутерами.

**Два автоматических стража, которые держат приём:**
1. Тест на «однострочный декоратор + полнота capability» (`tests/test_roles_phase8.py`) — не
   даёт хендлеру спрятать второй decorator/carveout мимо реестра прав.
2. Тест-маркер размера (`tests/test_module_size_convention_260816.py`, ниже) — не даёт модулю
   незаметно дорасти обратно до god-файла.

**Жёсткий потолок в тесте.** Порог ~800 строк — это ориентир для ревью, не жёсткий CI-гейт: маленький,
осознанный перебор не должен ломать сборку. Поэтому тест использует HARD-потолок в **850 строк**
для любого файла, которого нет в списке исключений — с запасом чуть выше ориентира, чтобы
случайные +10..+40 строк не роняли CI, а настоящее регрессивное разрастание — ловилось.

**Известные исключения (зафиксированы поимённо в тесте, не общим послаблением порога):**

Источник истины по потолкам — `tests/test_module_size_convention_260816.py::KNOWN_OVERAGES`;
таблица выше — человекочитаемая копия и может отставать. Расходятся — прав тест.

**Как осознанно поднять потолок.** Если модуль из таблицы выше вырос ЕЩЁ и это оправдано (новая
фича, а не заброшенный код) — потолок в `tests/test_module_size_convention_260816.py` правится
**в том же коммите**, что и рост файла, с обновлённой причиной в комментарии рядом с числом (и,
по-хорошему, строкой в этой таблице). Не понижаем и не удаляем чужие лимиты «заодно» — трогаем
только свою строку. Если новый файл (не из списка) перевалил за 850 строк — это НЕ повод сразу
добавлять его в исключения; сначала проверить, не пора ли резать по шву (см. приём выше), и
только если разрез объективно вреден — добавить с обоснованием.
