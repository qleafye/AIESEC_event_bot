# План доработок бота AIESEC Events

## Контекст

Бот используется для разных мероприятий AIESEC: форумы (YouLead), национальные конференции (RusCo) и др.
Решение: один универсальный бот с модульной архитектурой, не разделять на отдельные боты.
ТЗ: `ТЗ_Бот_YouLead.docx` — требования к Telegram-боту для форума YouLead (AIESEC).
Масштаб: 1000-1500 пользователей за сезон. На YL'26/1 — 1072 отобранных, в чат зашло 590 (55%).

---

## Что уже есть в боте

- Регистрация с динамическим flow (короткая/полная форма, настраиваемые вопросы)
- Синхронизация с Google Sheets (запись + кнопка синхронизации)
- Реферальные ссылки (`?start=USER_ID`, список приглашённых)
- Рассылки (всем / по файлу ID, альбомы, фото+текст)
- Админ-панель (статистика, экспорт CSV, настройки форума, управление вопросами, кнопки меню)
- Метки источников (`/create_link`, `?start=src_TAG`)
- Поиск пользователя `/find @username`
- Бонус за регистрацию (файл/фото после реги)
- Ответы на вопросы пользователей (reply в чате админа)

## Что нужно добавить

### Фаза 1 — быстрые wins

1. **Подтверждение реги** — после заполнения показать сводку "всё верно? / изменить". Клавиатура `get_confirm_kb()` уже есть, но не используется.

2. **Проверка подписки на канал** — `getChatMember` API. Простая реализация.

3. **Монеты + лидерборд** — фундамент для будущей геймификации:
   - Новая таблица `coins` (user_id, amount, reason, changed_by, timestamp)
   - `/coins @username +N` или `-N`
   - `/рейтинг` — топ-10 + место пользователя
   - Логирование каждого изменения

4. **Файлы при регистрации (резюме)** — принимать PDF/DOCX, хранить file_id в БД. Без OCR — менеджер сам смотрит.

### Фаза 2 — до запуска

5. **Верификация по базе отобранных** — при /start проверять TG-юзернейм в Google-таблице. Если нет — "отбор не пройден, вот ссылка на регистрацию".

6. **Рассылка по фильтру** — выбирать пользователей по критериям через inline-меню:
   - По полям БД: город, ВУЗ, статус, источник и т.д.
   - По дате регистрации: все кто зарегался после/до N даты
   - Комбинация фильтров (AND)

7. **Отложенные рассылки** — запланировать на дату/время. Нужен scheduler (APScheduler или asyncio loop), хранение в БД.

8. **Напоминание о дорегистрации** — автоматически пушить тех, кто начал flow но не завершил. Отслеживание FSM-состояния + scheduled job.

9. **Реферальные ссылки для амбассадоров** — формат `ref_[ID]`, статистика конверсии (переходов / зарегистрировалось), лидерборд амбассадоров. (УЖЕ ЕСТЬ!)

### Фаза 3 — потом

10. **Геймификация** (треки RESULT/INTERACTIVE/NETWORK) — система заданий, проверка менеджером. Нужно чёткое ТЗ на механику. Открытые вопросы ниже.

11. **Розыгрыши / бинго** — непонятный scope, откладывать.

## Ключевое архитектурное решение: регистрация → заявки

### Проблема
ТЗ требует: делегат заполняет форму, но менеджер вручную одобряет заявку. Текущая логика — сразу регистрирует.

### Решение: approval_mode toggle

**Сейчас:**
```
заполнил → finalize_registration() → add_user() + sheet + подарок + complete_text + меню
```

**Новый flow (manual):**
```
заполнил → submit_application(status=pending) + sheet + уведомление менеджеру
менеджер одобрил → approve_user() → complete_text + подарок + меню
```

### Что менять

| Компонент | Изменение | Файлы |
|---|---|---|
| БД | Поле `status` (pending/approved/rejected) | `db.py` |
| finalize | Разделить на `submit_application()` + `approve_user()` | `registration.py` |
| ensure_registered() | Проверять `status=approved` | `user_actions.py`, `db.py` |
| Админ-панель | Раздел "Заявки" (тиндер-формат) | `admin.py` |
| Настройки | Toggle `auto/manual` модерации | `admin.py`, `registration.py` |

### UI заявок — "тиндер для менеджера"

Рассматривали 3 варианта:

1. **Inline-кнопки под каждой заявкой** — сообщение в чат на каждую заявку. ❌ Отброшен: при 1000 заявках засорит чат.

2. **Раздел "Заявки" в админке с пагинацией** — ✅ Выбран как основной.

3. **Гибрид** — пагинация + batch-уведомления. По сути вариант 2 + напоминалка.

**Итоговый UI:**
```
📋 Заявка 3/47

👤 Иван Петров (@ivan)
🎓 ИТМО, 3 курс
📍 Москва
📎 Резюме: загружено

[✅ Одобрить] [❌ Отклонить]
[📎 Резюме]  [⏭ Пропустить]
[✅ Одобрить все (47)]
```

Нажал "Одобрить"/"Отклонить" — показывает следующую карточку.
"Пропустить" — вернётся потом.
"Одобрить все" — массовое одобрение.

**Напоминалка**: периодический таск, шлёт "⏳ 47 заявок ждут обработки" раз в N часов.

### Раздельные настройки для форм

Каждая форма (короткая/полная) получает свои настройки:

```
⚙️ Настройки регистрации

📝 Режим: [Краткая / Полная]

--- Краткая форма ---
  Поля: Имя + [настраиваемые вопросы]
  Модерация: [Авто / Ручная]

--- Полная форма ---
  Поля: Имя + [настраиваемые вопросы]
  Модерация: [Авто / Ручная]
  Резюме: [Вкл / Выкл]
```

**Юзкейсы:**
- Краткая + авто → как сейчас, быстрая рега без модерации
- Полная + ручная → тиндер-заявки для менеджера
- Краткая + ручная → менеджер проверяет но без резюме
- Полная + авто → все вопросы но без модерации

**Изменения в коде:**
- `REG_DEFAULTS` → два набора: `REG_DEFAULTS_SHORT` / `REG_DEFAULTS_FULL`
- `registration_mode` остаётся, определяет какой набор настроек грузить
- `approval_mode` → раздельный: `short_approval` / `full_approval`
- Админ-настройки: два экрана вопросов

## Универсальность: один бот для всех мероприятий

### Решение
Не разделять бот на отдельные инстансы для форумов и конференций. Один бот с модульной архитектурой — переключил настройки и готово.

### Почему один бот
- Регистрационный движок уже динамический (REG_FLOW с toggle вопросов)
- Рассылки, админка, статистика, Sheets — идентичны для всех мероприятий
- Два бота = двойной код, двойные баги, двойная поддержка

### Модульная архитектура

Настройки мероприятия в админке:
```
⚙️ Настройки мероприятия

📝 Тип: [Форум / Конференция / Кастом]
💰 Модуль оплаты: [Вкл / Выкл]
📋 Модуль согласий: [Вкл / Выкл]
🔔 Авто-напоминания: [Вкл / Выкл]
```

### Модуль оплаты (для конференций типа RusCo)

Референс: бот RusCo'26 — регистрация + оплата + напоминания + приём чеков.

**Настройки модуля (в админке):**
- Сумма взноса + damage fee
- Реквизиты (банк, номер карты, ФИО получателя)
- Дедлайн оплаты
- Шкала штрафов за отмену (настраиваемые даты + суммы)

**Flow пользователя:**
```
регистрация → "Когда планируешь оплатить?" → дата (валидация ДД.ММ.ГГГГ)
→ бот показывает: сумму, реквизиты, штрафы
→ "После оплаты отправь чек в PDF"
→ пользователь шлёт чек → менеджеру на проверку
→ менеджер подтверждает → "Оплата подтверждена!"
```

**Автоматические напоминания:**
- За 3 дня и за 1 день до дедлайна оплаты
- Периодичность настраивается

**Статусы оплаты:**
- `not_paid` — не оплачено
- `receipt_sent` — чек отправлен, ждёт проверки
- `paid` — оплата подтверждена
- `overdue` — просрочено

**Проверка чеков менеджером** — тиндер-формат (как заявки):
```
💳 Чек 5/23

👤 Иван Петров (@ivan)
💰 Взнос: 7900₽
📅 Дедлайн: 20.03.2026
📎 Чек: [прикреплён]

[✅ Подтвердить] [❌ Отклонить]
[📎 Чек]  [⏭ Следующий]
```

### Модуль согласий

Настраиваемый список согласий (toggle каждого):
- Согласие на обработку данных
- Согласие с политикой мероприятия
- Согласие на фото/видеосъёмку
- Кастомные согласия (добавляются через админку)

Показываются в конце регистрации перед финализацией.

### Новые типы вопросов в REG_FLOW

Для поддержки RusCo-формата нужны новые типы:
- `date` — дата с валидацией ДД.ММ.ГГГГ (дата рождения, дата оплаты)
- `consent` — автоматическое "Принимаю" (согласия)
- Остальные вопросы (ВК, аллергии, питание, проживание, волонтёрство) — обычные текстовые/выборочные, движок уже поддерживает

## Вопросы к создателям по геймификации

Без ответов на эти вопросы невозможно проектировать систему. Нужно получить конкретику от Head DXP / менеджеров.

### 1. Задания — что конкретно?

- Приведите 5-10 примеров конкретных заданий по каждому треку (RESULT, INTERACTIVE, NETWORK)?
- Задания одинаковые для всех делегатов или разные (персональные)?
- Задания появляются по расписанию (раз в неделю) или все доступны сразу?
- Есть ли дедлайны у заданий?
- Может ли делегат выполнить задание повторно?
- Сколько монет за каждое задание? Фиксированное или варьируется?
- Кто составляет задания? Менеджер через бот или заранее захардкожено?

### 2. Проверка выполнения — как именно?

- Какие задания проверяются автоматически (опрос, квиз, реферальная ссылка)?
- Какие задания проверяются вручную менеджером?
- Для ручной проверки — делегат присылает скриншот? Текст? Файл?
- Куда он это присылает — в бот или в отдельный чат?
- Кто проверяет — один менеджер или несколько? Как распределяются?
- Сколько времени на проверку? Есть ли SLA?
- Что если менеджер отклонил — делегат может переделать?
- Нужна ли причина отклонения?

### 3. Монеты и баллы

- Только начисление за задания или есть другие способы получить монеты?
- Можно ли тратить монеты на что-то (магазин, привилегии)?
- Или монеты — чисто рейтинговая валюта?
- Что получают топ-N в лидерборде? Призы?
- Баллы сгорают в конце сезона?
- Были проблемы со слетанием баллов — что конкретно происходило? При каких действиях?

### 4. Треки — зачем три?

- Делегат обязан выполнять задания из всех треков или выбирает один?
- Есть ли отдельный рейтинг по трекам или один общий?
- Влияет ли трек на что-то кроме группировки заданий?
- Ограничение "не более 3 активных заданий в неделю" — это 3 по всем трекам суммарно или 3 на каждый трек?

### 5. UI в боте

- Делегат видит список доступных заданий? Или они приходят push-уведомлением?
- Формат задания: текст? Фото? Видео? Ссылка?
- Как делегат отмечает выполнение — кнопкой в боте? Отправкой файла?
- Нужен ли прогресс-бар / трекер выполненных заданий?

### 6. Временные рамки

- Геймификация запускается сразу после регистрации или в определённую дату?
- Длительность: от начала до дня форума? Или есть фазы?
- Новые задания добавляются по ходу или всё заранее?

### 7. Антипаттерны прошлого YL

ТЗ упоминает:
- "Не более 3 активных заданий в неделю — перегруз приводит к дропу"
- Какие ещё проблемы были с геймификацией на YL'26/1?
- Что работало хорошо и надо сохранить?
- Какой % делегатов реально участвовал в геймификации?

### 8. Масштаб для оценки сложности

- Сколько всего заданий за сезон ожидается?
- Сколько менеджеров будут проверять задания?
- Пиковая нагрузка: сколько заданий на проверку в день?

| Роль | Кто | Доступ |
