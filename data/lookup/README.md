# Справочники ВУЗ/город (`lookup_entries`) — офлайн-снапшоты

Phase 30 (30-02, A2-03): бот стартует со справочником типа шага `lookup` («Анкета 2.0»)
**без единого обращения к внешнему API в рантайме** (30-CONTEXT.md, решение владельца №1,
второе поверх решения от 03.09 — ДаData/Getgeo не используются ни в каком виде). Оба файла
этой папки — `universities_ru.json` и `cities_ru.json` — читает `database.db.init_db()`
(`seed_lookup_from_snapshot`) один раз при пустой таблице `lookup_entries` для данного `kind`.
Снапшот **не синхронизируется автоматически** — это разовая выгрузка, обновлять вручную
командой ниже.

## Как обновить

```
python tools/seed_universities.py                 # сухой прогон — печатает статистику
python tools/seed_universities.py --apply          # перезаписывает оба файла
python tools/seed_universities.py --from-config    # вузы без сети (config.UNIVERSITIES)
python tools/seed_universities.py --curated --apply # кураторская выгрузка (30-08, см. ниже)
```

## Вузы — статус ДО 30-08 (архив, 13.09.2026 утро): снапшот был НЕПОЛНЫЙ

**Живая сеть до `query.wikidata.org` была доступна** в момент выполнения задачи (контрольный
запрос прошёл, HTTP 200, ~2 сек) — это НЕ история про недоступность сети. Причина, по которой
снапшот всё равно взят из офлайн-фолбэка (`--from-config`, 11 названий из `config.UNIVERSITIES`,
без псевдонимов):

**Обязательная методика (30-CONTEXT.md п.3) дала непригодные для прямого показа делегату
данные.** Контрольный запрос (`VALUES ?class { wd:Q3918 wd:Q38723 wd:Q1371037 }`,
30-RESEARCH.md § Code Examples) вернул **472 записи** (совпадает с зафиксированным в
RESEARCH числом от 12.09). Обязательный transitive-closure запрос
(`wdt:P31/wdt:P279* wd:Q38723`, тот же фильтр страны) вернул **1187 строк** — расхождение
2,5× (порог из плана «больше чем в полтора раза» — превышен многократно, не промолчали).

Разбор причины: `wdt:P279*` (транзитивное закрытие подклассов) у Q38723 в Wikidata цепляет
объекты, не являющиеся вузами по существу. Конкретные строки из реального ответа
(2026-09-13, кэш запроса не сохранён в репозиторий — сырой ответ великоват и содержит мусор,
который мы сознательно не публикуем):
- «Council of Young Researchers of the Russian Academy of Sciences» — совет, не вуз;
- «Cоветская улица 9 к1» — АДРЕС в Красногорске, не название учреждения;
- «General Medicine Faculty of RostGMU» — ФАКУЛЬТЕТ конкретного вуза, не отдельное
  учреждение (после P749-склейки должен был стать псевдонимом РостГМУ, но в Wikidata эта
  запись не несёт `P749` на головной вуз, поэтому осталась отдельной строкой);
- множество записей без русской метки (`SERVICE wikibase:label "ru,en"` отдал английскую
  метку или голый Q-код — для делегатского поиска на русском это бесполезно).

После применения обязательных фильтров методики (P576 «закрыт» — исключено 42 записи;
P749 «филиал» — псевдонимом головного) в выборке остаётся 987 записей — и это ВСЁ РАВНО
слишком шумно, чтобы отдать делегату без ручной модерации (адрес, совет РАН, факультет —
не единичные случаи, весь список не глазами не вычитан).

**Решение исполнителя:** не расширять и не изобретать методику (плану это прямо запрещено),
но и не публиковать в делегатский поиск неотсортированный список с мусором — оставлен
офлайн-фолбэк `config.UNIVERSITIES` (11 названий, без псевдонимов, `meta.count_base` /
`count_closure` = 0, как и предписано планом для офлайн-фолбэка). Бот поднимается с
непустым (хоть и коротким) справочником; делегат вне списка находит свой ВУЗ через
«Другое» → `lookup_merge_queue` (тот же путь, что предусмотрен дизайном для любых пробелов
справочника).

**Открытый хвост (перенесено в `30-UAT.md`, план 30-08 — Wave 0 Gaps этой фазы уже
предусматривает такой сценарий):** полноценный сид вузов требует ручной курации выгрузки
(отфильтровать неуниверситетские записи, догрузить недостающую русскую метку) — либо более
узкого списка Wikidata-классов, либо постобработки перед публикацией. Пункт по филиалам
(`P749` → псевдоним головного) на текущем офлайн-снапшоте не проверить (в `config.UNIVERSITIES`
филиалов нет) — переносится в `30-UAT.md` вместе с полным сидом.

## Формат снапшота

```json
{
  "meta": {
    "source_query": "текст SPARQL-запроса или описание офлайн-фолбэка",
    "count_base": 0,
    "count_closure": 0,
    "excluded_dissolved": 0,
    "fetched_at": "2026-09-13 01:01:00",
    "merged_branches": 0,
    "curated": false,
    "license": "CC0 (Wikidata)"
  },
  "items": [
    {"canonical": "ИТМО", "aliases": [], "source": "config_fallback", "dissolved": false}
  ]
}
```

`merged_branches`/`curated`/`license` — необязательные поля (задача B, 30-08), присутствуют
только у снапшотов, собранных `--curated`; `database.db.seed_lookup_from_snapshot` их не
читает (только `items`), они для человека — README и SUMMARY-отчёты исполнителей.

`items` читает `database.db.seed_lookup_from_snapshot` (задача 1 этого плана) — каждый
`alias` (включая сам `canonical`) вставляется отдельной строкой `lookup_entries` через
`INSERT OR IGNORE`, нормализация — `services.lookup.normalize_alias`.
